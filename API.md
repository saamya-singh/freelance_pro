# FreelanceLedger HTTP API

Base URL: `http://localhost:3000/api`. Requests and responses use JSON. The browser uses a same-origin `ledger_session` HttpOnly, SameSite=Lax cookie. For non-browser clients, save the `Set-Cookie` header from login/signup and send it on subsequent requests. No bearer token is needed. Sessions are stored in MongoDB and remain valid across server restarts for 30 days or until logout. Serve the UI and API from the same origin.

Errors return `{ "error": "message" }` with HTTP 400 (invalid input), 401 (no/invalid session or login), 404 (unknown endpoint), 409 (duplicate email), 413 (body over 2 MB) or 500. All workspace endpoints require a session. `GET /health` is public.

## Accounts

| Method | Path | JSON body | Response |
| --- | --- | --- | --- |
| POST | `/auth/signup` | `{ "name": "Asha", "email": "asha@example.com", "password": "StrongPass123!" }` | `{ "user": { "id", "name", "email" } }`; sets cookie |
| POST | `/auth/login` | `{ "email": "asha@example.com", "password": "StrongPass123!" }` | Same as signup; sets cookie |
| POST | `/auth/demo` | none | Logs in as the seeded demo account; sets cookie |
| GET | `/auth/me` | none | `{ "user": { "id", "name", "email" } }` |
| POST | `/auth/logout` | none | `{ "success": true }`; clears session cookie |

Passwords are at least 8 characters. Emails are case-insensitive and unique. User passwords are never included in API responses. Profile email is the account identifier and cannot be changed from Settings. The forgot-password screen is a prototype only; it does not issue reset emails.

## Workspace

| Method | Path | Body | Response |
| --- | --- | --- | --- |
| GET | `/workspace` | none | All workspace resources |
| PUT | `/workspace` | Backup object with at least `clients` and `invoices` arrays | Updated workspace; provided fields replace their corresponding resources, omitted fields stay unchanged |
| DELETE | `/workspace` | none | Workspace after clearing clients, work, invoices, payments and activities; profile and tax preferences remain |

Workspace resources: `clients`, `work`, `invoices`, `payments`, `activities` (arrays); `settings`, `taxSettings` (objects). Imports never change the logged-in account ID or email. Extra backup metadata such as `exportDate`, `userId` and `version` is ignored.

## Individual resources

For each path below, `GET` returns the resource and `PUT` replaces its entire contents with the JSON request body. Array resources require arrays; object resources require objects. These are whole-resource operations, so send the complete updated array/object, including existing entries. An empty array removes all entries. IDs are generated by the frontend for individual records.

| Path | Type | Common fields |
| --- | --- | --- |
| `/clients` | array | `id`, `name`, `email`, `company`, `gstin`, `status` |
| `/work` | array | `id`, `clientId`, `project`, `date`, `hours`, `rate`, `status` |
| `/invoices` | array | `id`, `number`, `clientId`, `items`, `subtotal`, `taxAmount`, `total`, `status` |
| `/payments` | array | `id`, `invoiceId`, `amount`, `date`, `method` |
| `/activities` | array | `id`, `type`, `title`, `description`, `timestamp` |
| `/settings` | object | `name`, `email` (read-only), `businessName`, `gstin`, `pan`, `invoicePrefix` |
| `/taxSettings` | object | `financialYear`, `defaultRegime`, `newRegimeSlabs`, `oldRegimeSlabs` |

The server isolates resources by authenticated user. MongoDB uses three collections in `MONGO_DB_NAME` (default `freelanceledger`): `users` stores accounts and password hashes, `sessions` stores expiring sessions, and `workspaces` stores per-user business data. For concurrent edits on multiple devices, the last whole-resource PUT wins.

## Example (curl)

```bash
curl -c cookies.txt -H 'Content-Type: application/json' \
  -d '{"email":"rahul@freelancedger.in","password":"Password123!"}' \
  http://localhost:3000/api/auth/login

curl -b cookies.txt http://localhost:3000/api/clients

curl -b cookies.txt -H 'Content-Type: application/json' -X PUT \
  -d '[{"id":"cli_1","name":"Example Ltd","email":"billing@example.com"}]' \
  http://localhost:3000/api/clients
```

`GET /health` returns `{ "status": "ok" }` for health checks.
